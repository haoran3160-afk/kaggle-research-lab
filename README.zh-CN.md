# Kaggle Research Lab

**面向真实结果的 Kaggle 研究工作流 skill：学习领域知识，建立可信基线，探索不同机制，用完整评分和独立复审闭环。**

[English](README.md) · [Skill 入口](SKILL.md) · [系统研究](references/system-research.md) · [完整内容说明](docs/PACKAGE_CONTENTS.md)

## 为什么做这个项目

参赛需要能够改善最终结果的研究。这个 skill 把开源方案检索、领域学习、基线、专家发散、机制实现、实际比较、独立审查与版本交付接起来。复现是起点；后续围绕真实失分，改写、组合或补足已有方法。

研究视角包括数据与表示、模型、function calling、工具、Agent loop、context/memory、harness、稳定性、验证和候选选择。它们是开放视角，不是每轮必跑的清单。研究宿主的可靠运行、参赛 Agent 的能力和官方评测各自评价。

## 安装与使用

需要 Python 3.11+，以及能加载 skill、运行项目工具的 Agent 宿主。日常指令以中文为主，英文说明见主 README。

```bash
git clone https://github.com/haoran3160-afk/kaggle-research-lab.git
cd kaggle-research-lab
python scripts/install_skill.py
```

默认安装到 `~/.agents/skills/kaggle-research-lab`。其他宿主用 `--destination` 指定目录。安装包括九个工作流模块、全部活动引用、四个模板和七个原版上游技能及许可证；旧安装保存在技能发现目录之外。

向 Agent 提出：

```text
使用 $kaggle-research-lab 继续这个比赛：<比赛链接>。
先读项目当前状态，收取在途结果，定位最大可恢复失分，
基于成熟方法提出不同机制，实际完成下一项有判别力的实验。
默认免费资源，保持我的定时周期和时刻不变。
```

`workspace.py` 只保存工作记录。实际检索、实验、评分与决策由宿主完成；后台接续需要宿主自动化能力和本机在线。安装不自动创建定时任务或授予账户操作权限。

## 完整流程

1. **接题与学习**：核规则、指标和资源，建立先修图，实际打开课程/视频/文档/项目，筛选章节并安排练习。用户未答题不阻研究，AI备课不代表用户掌握。
2. **基线**：分别建立合法提交入口、强参照和真实部署入口，按预测、静态推理或交互赛型选择评估单位。
3. **研究**：从实际失败反推瓶颈，让必要专家独立提出竞争机制，把原始研究与开源实现转成自己的可执行改动。
4. **实验与独审**：比较完整任务表现、回归、稳定性和机会成本；独立审查从原件与真实入口找反例，反馈交回执行器后重新评分。
5. **持续接续**：等待只阻相应决定；推进可独立研究，按远端ID恢复。阶段改变时更新定时任务的内容，保留用户的周期、时刻和状态。
6. **采用与交付**：探索准入与最好版采用分开。按真实集成收益决定保留、补测、转向或关闭，完成必要 GitHub 交付及最终收尾。

## 怎样判断它有用

使用[七项效能评价](references/effectiveness.md)：结果增益、实验决策价值、发现到备选、专家拓宽选择、独审纠错、无人值守闭环和人的能力积累。

完整分母、负结果、未知、回归和追加成本都保留。多次挑中一次成功不等于稳定；局部测试或PR完成也不代表提分。新方案可以经历有界发展周期，不因小概率风险提前判死。

目前没有证据保证使用这个 skill 就会提高分数或获牌。其设计参考了历史比赛失利与真实 Agent 实验，也保留了探索未超越基线的事实。[经验与证据边界](docs/LESSONS.md)说明可迁移的内容。
