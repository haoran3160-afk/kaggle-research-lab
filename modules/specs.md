# 开放规格：让下一次运行有依据，不把探索锁死

新比赛启动时先读实际代码、规则与已有说明，建立适合本赛的最小文档入口。已有AGENTS、规格或runner记录能承担职责就直接适配，不再建同义文件。局部修复只更新影响下一步的内容，不重启整套文档流程。

## 默认三种职责

- `AGENTS.md`：稳定的协作约束、已授权范围、重要运行入口与记录位置；不维护每日余额、当前排名和实验排期。
- `SPEC.md`或已有等价文件：本赛目标、实际训练/推理/比较/提交入口、可修订假设与资源安排。规定需要回答的问题和可观察结果，保留方法自由。
- 现有workspace或一个`STATE`入口：champion、最新结果、在途作业、预算观察和下一命令。只选一个动态事实源，其他文档链接它，不复制更新。

验证口径复杂到SPEC难读时才拆`EVAL`；跨多个模块、长期影响实现的取舍才写短ADR。普通实验直接在现有记录写改变、观察和下一决定，不增设审批表、证书或目录层级。

## 三类约束要标明来源

| 类别 | 如何处理 |
|---|---|
| 官方硬规则 | 链接官方来源与读取日期；包括信息边界、允许数据/权重、运行/网络条件、提交窗口与次数。疑点先核规则，不能自行放宽。 |
| 用户授权 | 记录本场已给的付费/公开/提交/自治范围及后续变更。授权内自主推进，不每阶段重新等批准；超范围只阻对应动作。 |
| 临时假设或试验设计 | 标注尚待检验、比较对象、成本和何种结果会改变它。可按新证据修订，保留此前结果，不把旧假设写成永久禁令。 |

先发散不同机制。局部疑虑、低成功概率、原型缺接口优先变成最便宜探针；只有已证官方违规、根本不可实现或必要资源无可行替代等重大缺口才立即阻相应路线，并寻找可行改写。探索准入不要求先胜过champion，采用仍看最终consumer实际比较与非作者意见。

等待官方分数或远端任务时，继续可独立推进的完整基线：训练/资产准备→推理→评估→consumer集成与部署入口检查，或处理失败样本和下一机制探针。保留原job ID查同一对象，不能把等待变成无事可做，也不能重发未知操作。

## 可复制的AGENTS约束段

把方括号替换为本赛实际内容，合入已有AGENTS；不覆盖用户既有指令。

```markdown
## 比赛执行约定

- 目标与可执行入口看[SPEC或已有规格路径]；当前结果、champion、在途任务与下一动作只看[唯一workspace或STATE路径]。
- 遵守[官方规则URL]的信息、资产、运行和提交边界。未知规则先核对应来源；不把经验或临时方案当官方要求。
- 本场已授权：[实际范围]。授权内自主调研、实现、试验和交付；正式次数按实时规则、余量与用户本场目标安排，不继承别场每日一次限制。免费为默认，新增付费、公开发布等超范围动作才另行处理。
- SPEC中的模型、表示、路线、阈值与实验顺序可按证据修订。小疑虑转探针，重大已证缺口只阻相应路线；保留不同机制和有界发展周期。
- 不添加文件哈希、独审证书、统一硬评分、重复审批或不能改变下一步的防御与文档。运行版本、原始结果和实际远端ID足够定位；必要检查必须对应真实故障或比赛行为。
- 实际consumer表现、回归和完整成本决定采用；非作者挑战重要决定。测试通过、模块完成、PR合并不代表提分。保留champion，允许合法有界的未证优诊断。
- 远端执行未知先查原对象；等待时继续可独立推进的基线或研究。一个主代理维护动态记录，子任务返回原件与建议，不共同改调度状态。
- 读近处代码与manifest，尊重现有接口；按实际变更做最小相关验证。结果回到动态记录，SPEC只补影响后续执行的变化和理由。
```

## 按赛题填写的SPEC骨架

只保留有用项；不知道的写未知与核实动作，不填虚构命令或成绩。

```markdown
# [比赛名称] — 当前研究规格

## 目标与比较问题
- 官方任务、指标、完整分母与统计单位：[本赛定义]。
- 当前目标与需要解决的失败群：[目标；当前事实链接动态记录]。
- 当前要比较的control、consumer及判断问题：[质量/成本/等价/机制/官方诊断]。

## 来源与边界
- 官方硬规则：[URL、读取日期、数据/权重/信息/网络/时限/最终选择要求]。
- 用户本场授权：[动作、资源与正式额度使用意图；规则实况仍需读取]。
- 临时假设与未知：[假设、已暴露验证面、反证或最便宜核实动作]。

## 能真正执行的基线闭环
| 环节 | 实际cwd与命令或工具入口 | 输入/输出及观察 |
|---|---|---|
| 训练或资产准备 | [实际命令；仅推理任务写适用入口] | [来源、产物与可用性] |
| 推理与比较 | [实际命令] | [control、完整预测/轨迹、指标和失败样本] |
| 最终consumer与部署 | [真实评分入口；服务/离线等条件] | [实际挂载、模型、输出与最低运行检查] |
| 正式运行与收件 | [实际平台命令/入口] | [provider版本/ID、日志、成绩回收方式] |

## 探索、资源与决策
- 允许探索的不同机制及第一个区分探针：[不预设只有当前方法合法]。
- 本次control、输入/运行条件、成本上限和结果分支：[支持/反驳/不可比较各做什么]。
- 当前算力、在途责任、每日正式余量读取入口、截止与收尾预算：[实时值链接动态记录]。
- champion采用依据：[最终consumer比较、回归、成本、不确定性与非作者意见]；探针/诊断不自动采用。

## 恢复与修订
- 唯一动态入口：[workspace或STATE路径]；最新结果、远端作业和下一命令都在那里。
- 影响后续执行的变化：[日期：新证据→改动→下一验证；若无则不造变更日志]。
```

## 社区依据与本赛适配

- [AGENTS.md](https://agents.md/)提供可预测的项目指令位置与实际命令约定。这里用于稳定约束与入口，不复制会过期的调度事实。
- [GitHub Spec Kit](https://github.com/github/spec-kit)把需求、计划、实现和反馈连接起来，并允许按任务采用不同过程。这里取“问题与结果先明确、实现可比较”，不安装CLI、生成全套文件或强制每个研究点走完整SDD。
- [OpenSpec](https://github.com/Fission-AI/OpenSpec)强调可迭代、适配现有项目的规格与变更。这里取“小范围更新已有规格、保留变更理由”，不复制整套proposal/design/tasks目录与人工阶段审批。

这些是对竞赛研究的轻量适配，不声称社区框架原样提供本赛的自主执行或成绩保证。规格应帮助下一次真实运行；文档已够用时立即回到基线和实验。
