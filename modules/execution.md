# 执行与无人值守接续
输入：research选定的下一动作、可执行基线、预算和截止时间。

宿主实际运行项目命令/Kaggle工具。workspace.py只是可读工作记录，不会自己搜索、训练或评分。已有项目记录足够时直接复用；需要轻量持久接续时见workspace.md。一个比赛只有一个主写入者，专家返回建议和产物，不并行修改调度状态。

委派分清发送消息与启动任务。给已完成的子代理续作，要用能触发新回合的接口（本宿主为`followup_task`）；`send_message`仅传递消息，不能把投递成功当作已经执行，尤其不能因此让主线空等。

先复用项目的明确运行入口和按角色/平台固定的依赖；Python项目可用uv标准requirements锁与pip wheelhouse，避免误用全局环境或每轮浮动解析。已验证的环境保持复用。在已有授权内，按固定配方创建临时实例、离线应用既定任务依赖属于正常执行，不因“不重配环境”而停下询问；新增依赖只针对真实缺口。平台排队、配额或网络故障不靠反复重配依赖处理。

候选依赖验证工具时，基线应在真实工具子环境跑通一次规则允许的验证命令；主进程编译、导入或挂载wheels不能代替这一步。运行路径不变就复用结果，发现缺口只修相应角色，不改已完成实验或把整轮负结果抹成环境未知。

跨工具共用的命令需适配实际工作目录和路径转换；外层工具支持的虚拟路径，未必会在脚本内部的子进程字符串中转换。能用仓库相对路径就复用同一命令，不因此重建环境。

不额外计算或比对哈希；正常安装元数据原样保留（包括RECORD，不解析或比对其中摘要），不为回避哈希裁剪第三方包或修改其内置行为。复用/打包运行环境时，实际检查最终解包、路径和环境下所需组件的真实导入与使用，不能用打包前通过替代。

临时依赖环境和可再生缓存放在结果导出目录之外；只交付后续评分、训练或提交确实需要的产物，按真实来源收件，避免完整环境包阻塞已经完成的研究结果。

沿用成熟SDK的创建、更新与拒重语义，只检查会改变当前操作决定的条件；已确认的不可变版本可复用真实回执。写前记录目标、版本、用途、资源上限，收到后保存provider job/notebook/version/submission ID。写入响应未知时先查精确对象，不重发；确认仍在运行则监控同一job，CPU研究继续；明确未写入后才考虑再次发出。

收件和隔离评分命令已确定、主代理另有独立工作时，可把这两步交给一个有界单次子任务：只观察当前ID，终态收件即运行现有评分并回报。主代理保留决策与主状态所有权；消费者不重新派发、改源或修改用户定时，异常与未运行部分仍须明确。不要让已经完成的作业等到研究或交付结束才被评分。

消费者回报终态后，主代理先将结果、决定和下一动作写回唯一工作记录，再切换研究或派发新作业。摘要滞后时按实际回执对账，不能把旧的进行中状态重新发车。 摘要与官方或原生结构化报告冲突时，先定位本地读回解析，保留原始评分和判分规则；日志中的示例或断言文本可能含数字，不能混入最终统计，不因此重配环境。

资源：免费或用户已授权额度为默认，分别核对托管推理/API的AI额度、Notebook GPU/TPU时数、正式提交次数与并发槽位，不能相互推断可用性。只查本次使用的资源类型及真实仍在途的承诺，不沿用已结束比赛的历史预留、旧额度或准入门槛，也不为账户盘点加载它们的研究上下文。估计本次完整费用并留收尾余量；未知在途只影响实际共享的资源。相关远端动作受限时，继续可做的本地工作。每日额度可用不代表仍有并发槽位；遇明确业务拒绝，记录原因及可观察解除条件，条件实际改变后复核并接续原候选，既不机械重试，也不让旧错误永久冻结研究。

遇到真实预算拒绝，先分清官方硬限、参照方案自定值与入口实际生效值；共享额度不等于每个阶段都有余量。改动需同步配置、提示中的数值及实际参数转发，并核整个提交的期限与覆盖成本，不能只凭单题还剩时间就宣布预算应当加大。

持续托管时复用同聊天已有heartbeat，保留用户设置的周期、时刻和状态；作业状态变化不能作为覆盖用户定时设置的理由。仅在需要新建且用户未指定周期时才默认30分钟，已有设置只按用户新的明确要求修改。任务在当前会话能继续就直接继续。每次醒来读工作记录→查已受理作业→运行下一有价值动作→收结果→交progress核对当前版本并作决定→保存下一动作。原件和next_command比多份状态文档重要。

### 随进展更新续接说明

定时任务的执行说明也要维护。研究阶段切换、当前路线关闭、瓶颈或授权改变、进入最终提交/收尾时，检查旧说明是否仍会引导正确动作；会带回旧路线或漏掉新目标时就更新，不等用户提醒。普通轮询、同一作业仍排队或运行不触发改写。

先保存唯一工作记录，再读取宿主中原定时任务的实时配置，通过自动化更新接口更新原ID的执行说明；原样保留用户设置的周期、时刻、状态、通知偏好及其他无关字段。沿用一个任务，通常调整其内容与阶段即可，不为每个实验另建定时任务。不能直接更新时在原工作记录标明未同步，不能把本地草稿称为已生效。

说明保留比赛范围、状态入口、当前阶段目标和结果到达后的决策分支；具体run ID、候选队列、额度和命令从当前记录读取，不在说明里复制整段历史。删除已消费的派发命令、已关闭路线和失效限制，保留仍有效的授权、最好版和收尾条件。结果在途时明确可独立推进的研究；评分完成后转入独审、采用/转向及下一次实际比较，不能继续只查同一个已结束作业。

精简模板：继续[比赛]，从[workspace路径]和项目说明读取当前事实。当前阶段是[阶段]，要解决[瓶颈/目标]。先收取当前已受理作业；结果到达后[评分→独审→决策]，等待期间推进记录中依赖已满足的研究。执行并保存一个下一动作；不重开已关闭路线。阶段或目标改变后同步更新本任务说明，保留用户定时设置。


本地定时需要主机与应用在线；失联后从ID恢复。注册定时不等于实际醒来，首轮确认真实接续。闭赛后仍收完已受理结果；任务结束只按用户已有明确收尾授权处理定时，不能仅因一条路线停滞而擅自停用或删除用户设置。不要新建一套守护进程或重启用户暂停的旧任务。

远端启动时工作记录保存完整action快照（cwd、命令、目标、预期输出），换CPU工作或重启后仍可查精确对象。迟到任务结果只归档自身观察和建议，不覆盖当前计划或champion；主代理读取当前状态再明确重排。

## 等待期间的实际工作

正式评分在途不等于研究暂停。先指出哪个决定确实依赖这个job/成绩，例如是否采用正式迁移；不要把它扩大成全项目阻塞。再选依赖已满足、最可能改变下一决定的工作：真实模型Notebook小面板比较、打通基线训练/推理/判卷/consumer的缺口、按失败样本实现下一机制、复现有用公开方案。并行工作仍计入同一账户预算与在途责任，不能挤占已承诺作业和收尾余量。

主线等待且有独立可做工作时，尽量把一个有根据的备选推进到下一消费者能用：打开具体原实现、做最便宜的可执行性或区分探针，交下一命令与结果分支。只列搜索摘要或候选名不算准备完成；有理由暂不采用也有价值。已有研究够用时不强行再搜或新增作业，实际结果到达先收件反馈。

本机没有模型服务时，先发现当前平台已授权的托管推理/API入口、模型目录、可用范围与额度，以最小真实请求核实能否服务本次研究；某个入口的模型子集不代表平台完整目录，目录列出也不等于已成功推理。可行就复用现成服务，不先搭自托管GPU；托管路径不满足所需能力时再选择私有Notebook等可用后端。做最小有判别力的对照，固定与问题无关的条件；若模型或部署条件变化，就明确比较范围及成本，不把托管接口返回当修复率或正式环境等价。记录真实模型与工具活动、自己的输出、耗时和评分。参考答案保持在独立判卷侧，判卷环境无效时标未知并修复，不把未解读的零分当方法失败。

必要的文档、编译和测试只服务具体运行或决策；同一包无变化就不重复检查，也不以不断建候选目录、写报告或做摘要校验代替实际比较。情报和探针要交代结果如何改变下一步，不能回答就不消耗预算。新反馈若推翻原瓶颈，交research/progress调整方法或对照，不机械跑完旧队列。

确无值得做的独立动作才等待：在原工作记录留具体依赖ID或可观察条件、下次观察时间、条件满足后的命令；例如job终态→收件比较，或额度恢复且有已选实验→启动Notebook。不要只写“等结果”。当前会话已有可用反馈就立即接续，不需要用户提醒；未变化时不密集轮询，也不为保持活跃启动无信息运行。
