# 基线与真正的比较工具
输入：任务/指标、数据与资源、候选公开方案。

适配：优先原作者的可运行实现、比赛官方starter和平台已有工具完成训练/推理与结果收集。先发现当前平台已授权的托管模型/API与AI额度，按所需模型和工具能力选择现成调用路径，不把自托管GPU当基线的默认前提；需要自行加载或训练时再用官方CLI/SDK与Notebook算力。外部skill用于具体工程切片；OOF只用于适合的预测赛，不套到ARC/游戏。完成后返回编排器，不自动正式提交。

产出：可执行的训练/推理/评估命令或托管调用入口、真实基线成绩、逐样本预测或轨迹、时间/费用、正式入口可运行的最小版本。托管与正式环境的模型版本、量化或工具条件不同就注明比较范围，不把开发接口可用等同正式复现。用简单合法基线尽早打通；强方案缺权重时并行开发自己的方案。

分别回答提交协议是否跑通、强参照是否真实复现、本方是否有竞争力；前两项不能代替第三项。比较面板要覆盖当前失分：两者已满分的样本适合查回归或等价成本，不反复拿它证明新增能力。主线在开发面上反复选择后，重要采用另找合适的未暴露任务、不同条件或必要重复，不把同题换名当迁移。

代码代理试验先完整读公开题面，说明是否已给出修复位置或具体步骤；强提示样本适合检查执行、回归与条件能力，不充当新增自主解题的主要证据。输入缺少行为契约时，先查合法原问题与公开资料，把补充信息的价值和模型／策略改进分开。

评价：预测任务按真实群组/时间分布切分，预处理、target encoding、calibration和stacking只在相应训练折拟合，比较与不确定性按实体/时间群组等真实依赖单位计算；ARC保留全部query并区分生成覆盖与选错；单人交互看实际游戏进展与运行条件；对抗游戏看有代表性的响应对手和角色。不能控制seed就记录运行条件并估计波动，不造字段。

消费者：research可在同一调用路径比较候选，execution可直接执行命令。优先复用项目现有runner，不为统一格式重写它。Smoke只检查入口；质量由实际任务表现回答。
