# 效能评估：用真实结果找下一处改进

在用户要求评测、主要路线完成一波、或持续没有能力增长时使用。复用本项目已有输入、原始产物、官方回执和决策；不另建评测平台、统一总分或每轮检查表。结论可以是有效、有行动但未证收益、不足、未知，必须说明下一步会因此怎样改变。

## 七个问题

| 评价项 | 实际量什么 | 不足时怎样推进 |
|---|---|---|
| **结果增益**（baseline/progress） | 同一完整任务上的新增解决、回归与完整成本；可比时列胜/负/平及全部分母。正式分数单独保留所有观察。 | 没有超过当前champion就不宣称提升；局部信号到合适新任务或条件确认。天花板样本查回归，不能证明新增能力。 |
| **实验是否改变投入**（research） | 结果排除了哪个解释，实际采用、关闭或重排了什么；事前问题和观测能否区分这些解释。 | 仍缺同一关键观测时，不继续变参数；修一次最便宜的判别动作或换机制。真实负结果也可以有信息价值。 |
| **发现到可用备选**（intelligence/等待） | 原始公开机制→实际输入/入口核验→便宜探针或有依据的不采用→下一消费者。对照真实在途窗口和当时已知状态。 | 仅标题/摘要或不可执行命令不算交付；缩到可接入机制，或明确缺口。允许无新发现，不规定检索/仓库/探针数量。 |
| **专家是否拓宽选择**（MoE） | 独立提出的竞争机制、少数意见及对应区分实验，是否改变实际选择；作者和反方只是审查时如实标明。 | 避免先指定答案再召专家。重开一次有边界的独立发散，给不同机制留下可承担的探针，不用票数或专家数计分。 |
| **独审与解释是否纠错**（review/context） | 从原件发现的反例，及因此修掉的实现、收窄的结论、改变的采用或下一测量；产物交付和最终效能是否混淆。 | 让非作者挑战会改变决定的解释；没有问题也可能合理，不能为提高“发现率”编问题。缺证据保留未知。 |
| **无人值守是否完成闭环**（execution/specs/delivery） | 真实结果有没有变成评分、决定和下一动作；是否无故重发/丢账/要求用户救场；必要版本是否可用，交付是否挡住当前研究。 | 修实际断点并从原ID恢复；复用已验证环境/入口，守住用户定时。缺在线或工时记录时不伪算空闲率、效率或恢复耗时。 |
| **学习是否可转成能力**（learning） | 核心知识是否有合适章节、先修、时长和练习；只有用户自己的代码、解释、迁移练习才能证明掌握。 | 材料不适配就换难度或练习；用户未回应是掌握未知，不是让研究停止，也不把AI备课当学习成果。 |

这些是问题与证据口径，不是统一晋级阈值。各赛使用自己的评估单位：预测样本/时间群组、静态任务与全部query、交互世界与对手；不能把不同实验、反复暴露的题或诊断提交拼成独立样本成功率。

## 怎样使用已有记录

1. 抽取能改变决定的代表性成功、失败、缺失和等待窗口；保留反例。没有完整执行清单时说明抽样范围，不报全局覆盖率。
2. 先看最终consumer和官方结果，再用动作/错误/成本定位弱环节。工具调用成功、有效diff、正确修复是不同层次；非零命令也可能是预期复现，不能只凭退出码归因。
3. 每项写“事实与原件→当前结论→最小改变”。无需新表单，现有工作记录足够。跨模块只处理最影响下一结果的一项，其他结论保留待办或未知。
4. 把改变用于下一次实际动作，随后检查是否增加解决、避免回归或排除关键解释。没有收益或新信息就调整；不要把本次评测报告写成改版已提分。

必要时用真实决策片段做前后盲回放，隐藏后续成绩、允许多种合理动作，并由非作者评判。回放只测决策与退化，不是实跑收益；若旧版也能答对，承认问题更可能在执行落实，而不是凭新文案宣称优越。新改版的结果优越性仍要在后续实际比赛中验证。

方法依据：[OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)强调贴合真实任务、持续反馈和具体成功条件；[Anthropic agent evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)区分最终环境结果与解释过程的轨迹。这里复用其原则，不引入付费评测服务或全套框架。
