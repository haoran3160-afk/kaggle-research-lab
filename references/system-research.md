# 从系统损失到自己的改进

用于强参照复现后、主要路线停滞或准备改变系统设计时。目标是在本赛规则和完整预算内提高最终任务表现；以代码修复Agent为例，其他赛型替换相应系统环节。不要求每轮遍历所有维度或新建框架。

## 从结果反推瓶颈

先定义最终成功：在真实评测入口交付正确修复，并保留正常行为。把失败还原成具体因果链：可见任务与仓库→取得有效信息→形成修复假设→执行修改→消费验证反馈→选择最终产物→正式入口接受并评分。找出最早有证据偏离目标的环节，以及它的下游损失；同一失败可能有多个原因，证据不足时保留竞争解释，不按工具名或一次报错直接归因。

区分三种对象：负责研究的宿主工作流、参赛Agent及其harness、独立官方评测。harness是组织模型、工具、状态、上下文、预算与产物交付的运行机制；它是可研究变量。研究宿主的接续修好不等于参赛Agent变强，官方评测器也不属于可改进得分的对象。

以下是按问题选择的视角，允许添加当前材料暴露的新方向：

| 系统视角 | 从失败里追问什么 | 可接入的机制示例 |
|---|---|---|
| 任务、数据与表示 | 是否理解错契约、定位错代码或验证分布过窄？ | 结构/符号检索、程序分析、任务分解、失败群取样 |
| 模型与生成 | 假设错误、能力不足还是有效候选生成不够？ | 规则允许的模型/训练方法、推理分配、候选搜索；不可更换模型时研究可控部分 |
| 指令、规划与loop | 哪一步反复无效或未能转入修复？ | 阶段转换、状态驱动控制、执行式handoff、明确停止与提交语义 |
| function calling与工具 | 模型实际看到了什么接口，动作与反馈是否可用？ | 工具粒度、编辑接口、输出组织、执行错误恢复 |
| context、检索与memory | 关键信息是否丢失、过时或被噪声淹没？ | 按需检索、压缩、任务内工作记忆、规则允许的经验迁移；对照额外读取成本和负迁移 |
| harness与运行稳定性 | 工作目录、进程生命周期、状态、超时、清理、并发或产物快照是否损失正确工作？ | 真实运行入口、状态保留、超时传播、合法恢复、最终工作树与提交产物衔接 |
| 验证、反馈与选择 | 验证是否测到目标，反例是否被消费，正确候选是否被丢弃？ | 真实入口检查、可执行反馈、候选保留与选择、独立复审 |

能力、执行可靠性和资源效率会相互影响。不能默认模型越强、记忆越多、工具越多或多Agent越复杂就更好；也不能因增加结构有成本就提前否定有根据的新机制。

## 成熟方法转成我们的假设

按当前失败机制检索原始研究、官方实现及相关消融，实际查看要移植的代码/接口和实验条件。在现有实验记录中说明：来源机制→适用前提→本赛差异→我们的改动→预期减少的失败→最便宜的区分实验。论文效果与社区采用提供试验依据，不是本赛已证收益。

开源方案既可作为强参照，也可提供可拆解机制。复现之后允许针对缺口改写、跨方法组合或提出新表示；不把复现完成当研究终点，不把改名、同义提示或增加角色当创新。多位专家独立提出不同的因果解释与可执行机制，再按信息价值和完整成本选下一投入，不要求为每个维度配一位专家。

组合方案可以先测整体是否有用，出现信号后再做能改变采用决定的消融；不强迫所有有耦合的设计从第一步就单因素化。保留简单基线和完整机会成本，避免复杂系统只因多次重试或更多预算获胜。

## 用最终表现评价能力与稳定性

- 主结果：同一完整任务上的新增解决、回归、胜/负/平与全部分母，并列完整时间、模型/工具预算和成本。保留正式结果作为独立观察。局部语法正确、工具成功、非空patch、快速运行均只是解释信号。
- 有必要判断稳定性时：对有潜力的候选在预算内做有依据的重复、顺序变化或正常部署条件确认，观察最终解决的一致性、有效产物丢失及尾部成本。一次成功不证明稳定，一次失败不否定整条路线；不默认建立全环境矩阵或人为故障注入体系。
- 保留所有真实尝试。候选自身错误、预算耗尽、空产物计入实际负结果；真正未运行、收件缺失或判卷基础设施无效保持未知。报告已尝试/有效评分/未知的数量和原因，不能只保留成功运行而制造稳定性提升。
- 若采用多次候选生成或修正，比较整个预算策略。多次中挑一次成功的pass@k，不等于重复均能成功的可靠性；不把多次机会与基线单次公平等同。
- memory和经验只能来自规则允许的信息；同一题反复修好或记住解法，不作为未知任务迁移证据。既查新增能力，也查原有成功群的回归；重要采用再按实际风险选择合适的新任务/条件确认。

每轮最终落实：哪类损失减少了、哪些解释被排除、是否集成，以及一个下一可执行动作。无质量收益但确有信息增量可支持转向；始终没有新观测就换实验或机制。真正有效的改动才反馈进默认工作流，保留适用条件，不能把一次个案无限堆成通用规则。
